# Agent Instructions

Project rules for coding agents. `CLAUDE.md` imports this file, so Claude Code
and Codex read the same text.

## What this is

A parametric cable box in OpenSCAD: one model file,
`cable-box-parametric.scad`, built on BOSL2. Around it are a geometry
regression suite, a nine-preset library, release automation, and an
Astro + Starlight docs site in `web/`. Calibration coupons are maintainer
tooling in `_local/calibration/`, which is gitignored and absent from a fresh
clone.

## Commands

| Task | Command |
|---|---|
| Geometry suite (110 scenarios) | `python tests/run_tests.py [--filter NAME]` |
| Version consistency | `bash scripts/check-version.sh` |
| Standalone bundle | `python scripts/build_bundle.py` |
| Calibration coupons (local only) | `python _local/calibration/build_calibration.py [--only NAME ...]` |
| Preset library | `python scripts/build_library.py` (`--no-stl --no-png --no-glb` for metadata only) |
| Options guide | `python scripts/build_options_guide.py [--no-render] [--only SLUG ...]` |
| README images | `python scripts/build_readme_images.py` |
| Release assets | `python scripts/package_release.py`, then `python scripts/release_notes.py vX.Y.Z[-rc.N]` |
| Docs site | `cd web && npm ci && npm run build` |

## Model rules

- CI runs OpenSCAD 2021.01 with CGAL. The suite counts solids from CGAL's
  `Volumes:` line, which the Manifold backend does not print, so a nightly
  build with Manifold reports false failures. Test on 2021.01, or on a nightly
  with `--backend=cgal`.
- The suite fails any scenario whose log contains `WARNING` or `DEPRECATED`.
  An `echo()` that reports something to the user must avoid both words.
- New validation follows the authoring guide at the end of
  `docs/VALIDATION_RULES.md`: gate the check on its feature toggle, name the
  parameter the user typed, and document it there and in
  `docs/PARAMETER_REFERENCE.md` in the same change.
- Append scenarios to `tests/scenarios.json` as text. Never round-trip the file
  through `json.dumps`, which destroys the hand formatting and `_why` notes.
  Every new scenario should fail against the model before the fix.
- Do not edit the `.scad` while the suite runs. Scenarios read the file as
  they go, so an edit mid-run produces failures that belong to neither version.
- After editing the model, regenerate `tests/fixtures/missing_bosl2.scad` with
  `python scripts/regen_missing_bosl2_fixture.py`.
- Regenerated STLs and PNGs are not byte-stable, so a byte diff is not
  evidence of a geometry change. Compare canonical meshes instead, the way
  `build_library.py` does for GLBs.
- `build_library.py` rotates each GLB from OpenSCAD's Z-up into glTF's Y-up
  (`to_gltf_axes`). Keep that rotation, or every 3D preview lies on its back.
- When a default changes, re-run the library metadata build, so
  `library/index.json`, the notes, and `cable-box-parametric.json` match.
- BOSL2 is pinned by `BOSL2_REF` in `.github/workflows/scad-smoke.yml`. Change
  it only with `scripts/bump-bosl2.sh`; `release.yml` reads the same pin.

## Versioning and releases

- Versioning is [E-10 (versioning)](docs/internal/E-10_versioning.md). A change
  to default geometry is a **major** bump, even when it is small.
- `Model_Version` in the `.scad` and the top released section of
  `CHANGELOG.md` must agree; `check-version.sh` enforces it in CI.
- Pushing a `v*` tag runs `.github/workflows/release.yml`, which drafts a
  GitHub release with its assets. Never push a tag to test the workflow; a
  pull request that touches the release files runs it without releasing.
  `docs/RELEASE.md` has the full procedure.

## Docs site

- `docs/` is the source of truth. `web/src/content/docs/` is generated by
  `web/sync-docs.mjs` and is gitignored; never edit it.
- The site is served at `https://projects.prisantlabs.com/3d-cable-box-parametric-openscad/`.
- `three` must stay on 0.183.x while `@google/model-viewer` 4.3.x pins it as a
  peer. Verify any dependency change with a clean `npm ci`, not `npm install`,
  because only `npm ci` enforces the peer range the way CI does.

## Planning docs

- Efforts live in `docs/internal/` and are listed in its `README.md`.
  Unscoped ideas and open problems are in `docs/internal/BACKLOG.md`.
- Always write an effort ID with its handle, such as "E-03 (openings array)",
  never a bare "E-03".
